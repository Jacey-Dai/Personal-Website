# Jacey’s Personal World — 视觉重设计 PRD / Claude 交接

版本：2026-10-24。用途：指导 Claude 接手现有网站的美术方向、材质、排版与体验打磨。

文档以中文沟通；网站正式内容和界面使用英文。本文件记录用户已表达的要求，并将建议的实施流程、指标单独标为建议；不代表用户已选择新的最终风格。

## 1. 本次要解决什么

用户认可「海洋包围的漂浮个人岛屿＋可进入的建筑」以及当前探索交互方向，但不喜欢现在网站的整体审美。此次任务是提升视觉品质、材质表现、构图和整体一致性，让它成为值得探索、具有个人辨识度的小世界。

目标感受：打开时想继续逛；走近能看到材质和有意义的细节；阅读时能快速理解 Jacey 的背景。受众包括 recruiter、同学、老师、合作伙伴与社交媒体访客。

成功不等于只换一套颜色、增加装饰动画或换字体。需要同时处理地形与海岸的轮廓、建筑比例与分组、植物形态、材质、光照、界面与场景的关系，以及室内外的连续性。

本次不要求新增真实项目、不重新虚构个人定位，也不要求换框架。

## 2. 必须继承的世界概念

五层概念需要同时存在：

| 层次 | 在网站中的作用 |
| --- | --- |
| 迷你星球 | 这是一个完整、紧凑、属于 Jacey 的个人世界；不需要真实球体 |
| 想象岛屿 | 统一的外轮廓、地形、海岸和周围海水 |

| 个人探索地图 | 路径组织不同地点，明确入口和关系 |

用户选定的构图方向：**B 的弧面漂浮岛＋轻微等距建筑，结合 A 的海水、小船、码头和短桥。** 海洋提供继续探索的想象；主要内容仍集中在一座容易理解的小岛上。

禁止将它缩减为单纯的街区、普通 portfolio 卡片页、真实地球仪或需要远距离拖动的游戏地图。不要增加复杂三维世界、角色操控、强制任务和无法跳过的开场动画。

## 6. 不能回退的交互要求

1. **首页只展示地图世界与必要导航。** 不在底部陈列全部建筑、项目卡片或介绍长页；桌面和手机都适用。
2. 建筑名字与用途在鼠标悬停／键盘焦点时出现，不默认铺满地图。提示应含地点名、标准栏目名、一句内容预告，不遮住其他主要入口。
3. 触屏保留第一下识别、第二下进入；快速导航一次点击即可到达。不依赖 hover 才能使用。
4. 点击建筑进入对应空间；过渡短、可理解。可使用轻微靠近，但不得为动画增加等待。
5. 访问后改变建筑本身，例如窗灯、旗帜、门牌或局部陈设。文字 `visited`、计数器或导航颜色变化不能单独满足要求。
6. 已访问状态在本地保存，有重置入口；不解锁或限制任何内容。
7. 室内保留建筑性格：工作室像工作室、博物馆像博物馆、花园像花园。可点击真实空间中的物件，再打开易读的 HTML 内容。
8. 阅读层保留场景联系，但正文对比度、行长、滚动和链接优先。长篇文字不能烘焙进图片。
9. 关闭阅读层回到物件所在室内，再关闭回到原地图位置。Escape、关闭按钮、浏览器返回和焦点恢复保持一致。
10. 固定快速导航始终提供 About、Projects、Experience、Beyond、Resume、Contact；Currently 也有明确入口。
11. Resume／Contact 可直接到达，不强迫完整探索；保留 `#resume`、`#contact` 和其他已有分享链接。

## 7. 手机端与无障碍

原始讨论曾建议纵向路线，但用户后续明确要求首页地图化；**当前要求优先，不能自动恢复下方卡片列表。** Claude 可以提出新的手机构图，先用实际屏幕样张证明五个入口可达，再决定是否改变现有裁切。

- 在 320、390、768、1440px 宽度检查；手机上的入口和导航不能因裁切而消失。
- 主要按钮建议至少 44×44 CSS px；地图中相邻热区不可大面积重叠或误触。
- 键盘能识别并进入建筑、选择物件、阅读、关闭、恢复焦点；焦点样式可见。
- 支持 `prefers-reduced-motion`，停用装饰循环和不必要的缩放／位移。
- 正文达到 WCAG AA 对比度目标（普通文字 4.5:1，大字 3:1），不只靠颜色表达状态。
- 触屏不把悬停动画作为必经操作；装饰不拦截点击。

## 8. 美术与素材策略

### 用户已经提供的来源

- Medieval Village MegaKit Standard：https://quaternius.com/packs/medievalvillagemegakit.html
- Downtown City MegaKit Standard：https://quaternius.com/packs/downtowncitymegakit.html
- Stylized Nature MegaKit Standard：https://quaternius.itch.io/stylized-nature-megakit

原文件在仓库的 `assets/source-packs` 分支，固定提取源提交为 `7b16930628d5adc01c6e5f98afde99199ea21e3a`。文件夹实际拼写是 `assests/`；不要未经迁移直接纠正路径。

现有 `tools/extract_art_sample.py` 提取选中的 glTF 及依赖，不把全部源包放进网站。已有许可证见 `docs/licenses/`，记录为 Standard 包 CC0 1.0；新引入文件仍需核对具体来源与许可。Downtown 已提供，但不要求为使用而混搭城市建筑。

### 美术建议，待视觉样张验证

- 优先测试模型原有的屋瓦、木材、石材、墙面、窗户纹理，再决定局部统一；不要再次全部覆盖成纯色。
- 原纹理不是不可修改。可调整色相、粗糙度、纹理密度和光照，使不同模型形成同一个世界。
- 树木重点处理叶片透明、法线、受光与阴影；避免黑叶、透明边缘错误和整团同色。不能假设免费 Standard 包附带展示图中的完整引擎 shader。
- 用主次控制色彩：海洋与地形提供大色面，建筑群形成中层节奏，少量亮色引导内容入口。具体色值不要在看样张前锁死。
- 地形、建筑和植物需要接地阴影与尺度关系；不能通过一层统一滤镜代替材质工作。
- UI 的字重、边框、纸张与按钮需有统一规则，避免每个房间换成完全无关的应用界面。
- 不混入不相容的库存插画或生成图；如使用新素材，要说明理由、可编辑方式和许可证。

动效建议控制在少量细节：水面、船、灯光或工作设施。预渲染整张图中的物件不能假装天然具备独立动画；需要拆层或替换素材时应说明成本。不要只为视觉改造添加重型运行时。

## 11. 建议实施阶段与交付物

### Phase 1：审美审查与方向提案

先启动当前版本，查看桌面、手机和至少两个室内，提供带截图的具体问题清单。提出 **2–3 个确实不同的方向**，区别体现于形体、材质、光照和 UI，而不只是三套配色。每个方向说明要保留什么、修改什么、使用哪些现有素材、预计成本。

推荐一个方向，并做一块高可信度样张：海岸／海水＋一栋上传素材建筑＋一棵树或一组多肉＋悬停提示＋对应室内小样。提供可见图片或可打开的文件，不能只说“已经生成”或只给文字。

**建议在用户选定视觉样张后再全面应用**。需要用户选择的只限美术方向；环境检查、资产核实和样张准备可先完成。

### Phase 2：完整外部世界

应用选定的材质与光照；整理岛屿轮廓、路径、建筑比例、植物和海上设施；完成桌面／手机构图、hover／focus 提示、访问前后建筑状态。提交全景、手机、访问前后对比图。

### Phase 3：室内与阅读系统

应用到五个空间和相应物件；统一室内外材质及尺度逻辑，打磨 HTML 阅读排版；保持快速访问与层级返回。提交工作室、博物馆、花园的进入与阅读示例，其他房间也必须完成。

### Phase 4：验证与交接

执行构建与相关交互检查，记录实际结果与未完成项；更新素材来源、设计 token、场景再生成命令、决策记录。提交前后对比，确认发布状态，明确区分“代码已推送”“部署成功”“线上实测”。
